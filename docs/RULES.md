## 품명 조합

경영박사 품목코드는 네 요소를 순서대로 붙여 만듭니다.

```
{색상코드}-{타입}/{종류}          예) B200(IV)-L18/원코드
```

| 조합 | 형태 | 마스터 등록 수 |
| --- | --- | --- |
| 투코드 (기본) | `B001(CP)` | 183 |
| 원코드 | `B001(CP)-원코드` | 62 |
| 셔터 | `B001(CP)-셔터` | 62 |
| DI 전용 | `B001(CP)-DI` | 62 |
| 원코드 + DI | `B001(CP)-원코드/DI` | 62 |
| L18 원코드 | `B001(CP)-L18/원코드` | 62 |
| L18 투코드 | `B001(CP)-L18/투코드` | 62 |
| L18 셔터 | `B001(CP)-L18/셔터` | 7 |

**규칙 두 가지**

- 투코드는 종류를 표기하지 않습니다 (기본값)
- L자(`L18`)에는 DI 전용 코드가 없습니다. DI 도 같은 단가를 씁니다

`규격` 열은 품명에서 자동으로 결정됩니다. `-L18/원코드` → `0.18mm/원코드`.
별도 매핑표 없이 마스터에서 조회합니다.

## 금액 계산

```python
from decimal import Decimal, ROUND_HALF_UP

# 1) 면적(헤베) — cm → m, 소수 둘째 자리 반올림
raw  = (Decimal(가로) / 100) * (Decimal(세로) / 100)
헤베 = raw.quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)

# 2) 최소 수량 — 1.5 미만이면 수량 열 자체를 1.5 로 대체
수량 = max(헤베, Decimal("1.5"))

# 3) 금액 · 부가세 — 원 단위 반올림
금액   = (Decimal(단가) * 수량).quantize(Decimal("1"), rounding=ROUND_HALF_UP)
부가세 = (금액 / 10).quantize(Decimal("1"), rounding=ROUND_HALF_UP)
```

**검산**

```
110 × 235  →  1.10 × 2.35 = 2.585  →  2.59
2.59 × 21,300 = 55,167  →  부가세 5,517          실제 전표값과 일치

 60 × 120  →  0.60 × 1.20 = 0.72   →  최소 1.5 적용
1.5 × 21,300 = 31,950  →  부가세 3,195
```

### 왜 Decimal 인가

```python
round(2.585, 2)                                    # 2.58  ← 틀림
Decimal("2.585").quantize(Decimal("0.01"),
        rounding=ROUND_HALF_UP)                    # 2.59  ← 맞음
```

부동소수점은 `2.585` 를 정확히 표현하지 못합니다.
금액을 다루므로 전 계산을 `Decimal` 로 처리했습니다.

## 장부 표기

### 열 구성

| 열 | 내용 | 정렬 |
| --- | --- | --- |
| A | 수기 체크칸 (비움) | 가운데 |
| B | 상호 + 내부표시 | 오른쪽 |
| C | 색상 | 왼쪽 |
| D | 가로 | 오른쪽 |
| E | `X` | 가운데 |
| F | 세로 | 왼쪽 |
| G | 수량 | 가운데 |
| H | 모형_1 (방향) | 왼쪽 |
| I | 모형_2 (손잡이) | 오른쪽 |
| J · K | 기재사항 | 가운데 |
| L | 출고일 | 가운데 |

규격(D·E·F), 모형(H·I), 기재사항(J·K) 그룹 **안쪽에는 세로 테두리가 없습니다.**
정렬도 그룹 가운데를 향해 마주보게 배치합니다.

### 특수 표기

| 표기 | 의미 | 위치 |
| --- | --- | --- |
| `"` | 위 행과 세로 규격 동일 | 세로 열 |
| `#` | 연창 (원코드만) | 손잡이 앞 또는 기재사항 앞 |
| `☆` | 택배 · 화물 배송 | 색상 열 |
| `(K)` `(N)` `(1)` | 내부 관리 표시 | 상호 뒤 |

**`"` 조건** — 색상이 같고 세로가 같을 때만. 색상이 다르면 세로가 같아도 적습니다.
휴안은 이 표기를 사용하지 않습니다.

### 부분 서식

셀 안의 일부 단어만 색이 다릅니다.

| 단어 | 색 |
| --- | --- |
| `원코드` | 초록 |
| `셔터` | 빨강 |
| `틀안` | 파랑 |
| `선불` | 빨강 |

상호 열은 코드가 14pt, 내부표시 `(K)` 가 11pt 입니다.
글꼴은 `THE행복열매` 이며, 리치텍스트의 **모든 조각에 글꼴을 명시**해야
색이 없는 부분이 기본 글꼴로 떨어지지 않습니다.

### 배송 행

택배 · 화물이면 상품 행 아래에 특수 행이 붙습니다.

```
☆  |  주소 (2행까지 분할, 동호수는 101-202 로 축약)
   |  수령인 · 연락처                            선불 (빨간 글씨)
   |  전달 : ...
```

주소가 길면 어절 단위로 두 행에 나눕니다.

## 작업지시서 변환

장부에서 다음을 제거하고 단순화합니다.

| 장부 | 작업지시서 |
| --- | --- |
| `JO (K)` | `JO` |
| `B 원코드 200` | `원코드 200` |
| A열 `O` | 표시하지 않음 |
| `☆` 주소 행 | 제외 |
| `#` 포장비용 행 | 제외 |
| 규격 · 수량 · 모형 · 기재사항 · 출고일 | 그대로 |

**구조**

- 한 시트 = 제작용 블록 (16행) + 확인용 블록 (16행), 내용 동일
- 각 블록에 날짜와 헤더를 따로 넣습니다
- A4 절반에 인쇄하므로 블록당 16행
- 업체 묶음은 중간에서 자르지 않고 다음 `현장(n)` 시트로 넘깁니다
- 상호 · 색상은 가운데 정렬

## 손잡이

### 기본 길이

주문서에 길이가 적혀 있으면 그 값을 우선하고, 없을 때만 기본값을 적용합니다.

| 종류 | 세로 조건 | 기본 길이 |
| --- | --- | --- |
| 원코드 | 210 이상 | 손150 |
| 원코드 | 210 미만 | 손130 |
| 투코드 | 210 이상 | 손150 |
| 투코드 | 210 미만 | 손100 |
| 셔터 | 210 이상 | 손150 |
| 셔터 | 100 이상 210 미만 | 손100 |
| 셔터 | 100 미만 | 세로보다 짧게 (10단위 내림) |

**기본값과 같으면 장부에 적지 않습니다.** 다를 때만 적습니다.

길이는 10단위만 사용합니다. 5단위가 들어오면 내림하고 확인 대상으로 표시합니다.
`줄55` → `손50` + 확인.

### 방향

- 발주서 표기를 그대로 사용
- 미기재 시 우측이 기본값이며, 전표 사원코드는 좌 = 1, 우 = 2
- **우측은 장부에 적지 않습니다** (기본값이므로)

### `봉` 표기 주의

거래처에 따라 뜻이 다릅니다.

- **M(미더스)** — `봉` 은 손잡이를 가리킵니다. `우(봉50)` → 방향 우, 길이 50
- **그 외** — 투코드에서 `봉` 은 손잡이와 별개 부품일 수 있습니다.
  기재사항에 원문을 남기고 확신도를 낮춰 확인 대상으로 표시합니다

## 배송

거래처만 알면 대부분 결정됩니다.

| 거래처 | 배송 방식 | 장부 표기 |
| --- | --- | --- |
| DI | DI/SP | (별도) |
| 휴안 | 택배 | `목(택배)` |
| 커블리 | 내사 | `목(내사)` |
| M · DD · DU · JO · JL | 오전 배달 | 표시 없음 |
| **RT** | 화물 또는 택배 | 주문서로 판별 |

RT 만 분기가 필요합니다.

- 화물 지점명이 있으면 → 화물
- 택배 주소가 있으면 → 택배
- 둘 다 없거나 둘 다 있으면 → **자동 결정하지 않고 오류 표시**

배송 방식이 틀리면 `☆` 표시, 주소 행, 선불 표기가 전부 어긋나므로
자동 판정을 하지 않습니다.

## 검증 규칙 15개

### 차단 (`red`) — 수정 또는 수동 해제 필요

| 코드 | 조건 |
| --- | --- |
| `가로누락` | 가로 치수 없음 |
| `세로누락` | 세로 치수 없음 |
| `품목미등록` | 마스터에 없는 색상코드 · 조합 |
| `단가없음` | 해당 등급 단가가 0 |
| `최소사이즈미달` | 종류별 최소 가로 미만 |
| `거래처불명` | 거래처 판별 실패 |
| `배송판별불가` | RT 인데 화물 · 택배 구분 불가 |
| `창개수불일치` | 발주서 메모의 총 창 수와 추출 행 수가 다름 |
| `변경-출력됨` | 이미 출력한 주문의 변경 — 재출력 필요 |

`창개수불일치` 는 발주서에 적힌 `총 12창` 같은 메모와 대조합니다.
행이 누락되는 오류를 자동으로 잡는 장치입니다.

### 중복 · 변경 (`review`) — 표시만, 다운로드 가능

| 코드 | 조건 |
| --- | --- |
| `중복` | 거래처 · 품목 · 치수 · 수량 · 손잡이 완전 일치 |
| `중복의심` | 치수 ±1 cm 이내 |
| `과거중복` | 최근 7일 주문과 동일 |
| `변경의심` | 최근 2일 유사 주문 존재 (가로 또는 세로 한쪽만 비슷) |
| `변경요청` | 캡처에 "변경되나요" 등 수정 요청 문구 |

**자동 삭제하지 않습니다.** 같은 집에 똑같은 창이 실제로 있을 수 있습니다.

중복 판정과 변경 판정의 기준이 다릅니다.

```python
# 중복 — 가로와 세로가 모두 비슷
similar():         near(가로) and near(세로)

# 변경 후보 — 한쪽만 비슷 (치수가 바뀌는 것이 정상이므로)
change_candidate(): near(가로) or  near(세로)
```

### 확인 (`yellow`)

| 코드 | 조건 |
| --- | --- |
| `치수순서의심` | 가로 > 세로이고 세로가 100 미만 |
| `치수범위이상` | 10 ~ 400 cm 범위 밖 |
| `확신도낮음` | 판독 확신도 0.8 미만 |
| `손잡이미기재` | 방향 없음 — 우측 기본 적용 |
| `손잡이길이보정` | 5단위 → 10단위 내림 |
| `봉표기모호` | M 이외 거래처의 투코드 + `봉` 표기 |

### 예외 (`info`)

수리 · 롤스크린 · 홀딩도어 · BMIX · 부속 · 레일은 장부에서 제외하고
별도 알림 목록으로 표시합니다.

## 역산 과정에서 발견한 오류

### 단가 등급표가 반대로 되어 있었다

회사에서 받은 거래처 단가등급표와 실제 전표가 맞지 않았습니다.

```
제공된 표     DI = 출고I가 ,  휴안 · DU · JL = 출고L가

검증          실제 전표 179건이 전부 반대와 일치
              DI 전용 품목은 I가가 0원 — 계산 자체가 불가능
              휴안 실제 단가 23,000원 = I가 (L가는 23,100원)

조치          전표로 역산해 매핑을 정정
              이후 4,783행 전수 재검증 — 9개 거래처 전부 일치
```

I가와 L가만 서로 바뀌어 있었고 A가 · H가는 맞았습니다.
무작위 오류가 아니라 두 항목만 스왑된 형태여서,
캡처 실수보다는 시스템 표기 문제로 보입니다.

### 변형 품목이 기본 품목을 덮어썼다

마스터에 `B027(SV)` 와 `B027(SV/펄無)` 가 함께 있어,
코드 → 품명 매핑을 만들 때 나중 값이 앞 값을 덮어썼습니다.
휴안 발주 1건에서 품목 조회가 실패했습니다.

괄호 안에 `/` 나 `無` 가 있으면 변형으로 보고
기본 품목을 우선하도록 수정했습니다.

### 파일마다 엑셀 열 구조가 달랐다

DI 발주서의 6번 열이 파일에 따라 `원/투` 또는 `커버/점보` 였고,
후자에는 값이 비어 있거나 `원` 이 들어 있었습니다.
헤더 이름만 믿으면 178건이 전부 부속으로 분류됩니다.

헤더로 열을 찾되 **종류는 값을 보고** 판단하도록 바꿨습니다.

### 작은 캡처는 표를 읽지 못했다

782 × 537 px 캡처에서 12행 표 중 8행만 추출되었습니다.
셀 하나가 몇 픽셀 수준이라 판독이 불가능했습니다.

업로드 시 긴 변을 1,600 px 이상으로 확대하도록 바꾸자 12행이 정확히 나왔습니다.
정보가 늘어나는 것은 아니지만, 이미지 타일 수가 늘어
같은 영역에 더 많은 시각 토큰이 배정됩니다.
